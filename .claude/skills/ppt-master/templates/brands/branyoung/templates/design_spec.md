## II. Color Scheme

| Role | HEX | Provenance | Notes |
|---|---|---|---|
| primary | `#E8332B` | user | 빨강 — 핵심 키워드, 결과 단어, 경고성 문장, 수치 강조, 표지/구분 배경 |
| secondary | `#C9A227` | user | 겨자색 — 보조 강조, 구분 슬라이드 배경(빨강과 번갈아), 캐릭터 노란 가디건과 톤 연결 |
| text | `#111111` | user | 본문 기본색 — 순수 `#000` 금지 |
| bg | `#FFFFFF` | user | 콘텐츠 슬라이드 배경. 표지·구분 슬라이드의 글자색 |
| caption | `#666666` | user | 캡션 등 아주 보조적인 텍스트에만. 이보다 흐린 회색 금지 |

**절대 규칙 (강사 지정, 예외 없음)**

1. **본문 글씨 뒤에 색 배경을 넣지 않는다.** 카드(채워진 round rect), 알약형 뱃지, 색 채운 표
   헤더, 색 원 안의 아이콘 등 "텍스트를 감싸는 색 도형" 금지. 콘텐츠 슬라이드는 흰 배경 위에
   텍스트가 그대로 놓인다.
2. **강조색은 빨강·겨자색 두 가지뿐.** 오렌지/그린/네이비 등 다른 색, 그라데이션, 그림자, 글로우 금지.
   차트도 빨강·겨자·검정·회색(`#666666`)만 사용.
3. **강조는 단어 단위.** 문장 전체를 색칠하지 않는다 — 결과 단어나 핵심 수치 하나만 빨강/겨자.
4. **페이지마다 챕터명·분류 헤더·뱃지를 넣지 않는다.** 각 슬라이드는 그 슬라이드의 핵심 문장(또는
   질문) 하나로 시작한다.
5. **표지·챕터 구분 슬라이드만 예외**: 빨강 또는 겨자색 전면 배경 + 흰 글씨. 챕터가 바뀔 때
   빨강↔겨자를 번갈아 써서 전환을 표시한다.

| Role | Family | Weight |

**크기 위계 (강사 지정 — "글씨가 커서 좋다")**

| 요소 | 크기 (pt) | 색 |
|---|---|---|
| 표지 제목 | 48–54, 굵게 | 흰색 (빨강/겨자 배경 위) |
| 구분 슬라이드 제목 | 40–44, 굵게 | 흰색 |
| 콘텐츠 핵심 문장 (사실상 슬라이드 제목) | 30–36, 굵게 | 검정, 강조 단어만 빨강/겨자 |
| 한 문장형 슬라이드의 문장 | 34–44, 굵게 | 검정, 강조 단어만 빨강/겨자 |
| 본문 / 리스트 | 22–26 | 검정 |
| 캡션 · 아이콘 라벨 | 18–20, 굵게 | 검정 |

**본문 22pt 미만 금지.** 글이 넘치면 글씨를 줄이지 말고 문장을 줄이거나 슬라이드를 나눈다.

## IV. Logo

- 표지·마무리 바이라인 표기: `브랜영 김은영` (Dr.goods / Dr. Goods Nikey 표기 금지)

## V. Voice & Tone

- Formality: casual-professional (강의 구어체, "~입니다/~해요" 혼용 가능)
- Person: 청중에게 직접 질문 던지기 허용 ("나는 만드는 사람인가, 파는 사람인가?")
- Emoji: forbidden (슬라이드 본문)
- Abbreviations: spell-out-first-use — 전문용어는 바로 쉬운 말로 재번역
- Titles: 평서문보다 **질문형** 우선
- Opening: 충격적인 숫자·데이터로 문제를 열고 → "그럼 안 망하는 사람은 무엇이 다른가"로 반전
- Framing: "AI 기능 소개"가 아니라 "AI를 직원처럼 써서 사업 시스템을 만드는 것"
- Theory: 굿즈 소비가치 이론은 실전 언어로 — 쓸모 있어야 팔린다 / 보기 좋아야 선택된다 /
  즐거워야 기억된다 / 지금 사야 할 이유가 있어야 움직인다 / 나를 표현할 수 있어야 확산된다
- Every concept ends with "그래서 오늘 무엇을 만들어 가는가"

## VI. Icon Style

- Preference: linear

> `tabler-outline` 선화 아이콘을 **배경 원·뱃지 없이 그대로** 놓는다. 아이콘 색은 검정 또는 빨강/겨자
> 한 가지. 프로세스 번호는 **테두리만 있는 원(채우지 않음)** 안에 빨강/겨자 숫자.

## VII. Visual Assets

- Images and illustrations: `../images/`
  - `branyoung-pointing.png` — 가리키는 포즈. 표지, 핵심 메시지 등장 슬라이드
  - `branyoung-confused.png` — 갸웃하는 포즈. 문제 제기 / 질문 슬라이드, Q&A
- Usage: **매 슬라이드에 넣지 않는다.** 표지와 마무리(Q&A) 등 정체성이 필요한 자리에만 크게.
  콘텐츠 슬라이드는 여백을 두려워하지 않는다.

## VIII. Layout Grammar (free-layout guidance)

헤더 뱃지가 없는 대신 아래 패턴을 섞어 쓴다. 같은 패턴을 연속 반복하지 않는다.

- **한 문장형** — 큰 문장(질문 또는 단언) 하나만. 여백이 곧 강조
- **평문 비교 2–4열** — 표·카드 없이 굵은 열 제목 + 짧은 설명. 구분은 여백만
- **아이콘 + 라벨** — 선화 아이콘 아래 굵은 라벨
- **숫자 강조** — 핵심 수치 하나를 크게 빨강/겨자, 나머지는 검정
- **프로세스** — 테두리 원 + 색 숫자, 가는 연결선
- 표는 되도록 쓰지 않는다. 꼭 필요하면 셀 배경 없이 가는 구분선만

## IX. Speaker Notes (standing preference — always on)

- **모든 덱에 발표자 노트를 만든다.** 사용자가 "노트 빼줘"라고 명시하지 않는 한 `design_spec.md §X`를
  `None requested`로 두지 말고 노트를 요청된 상태로 기록한다 (강사 본인 지정, 2026-09-30).
- 톤: 강사 본인이 그대로 읽어도 되는 구어체 강의 멘트. 질문 던지기 → 사례/숫자 → "그래서 오늘 무엇을
  만드는가"로 연결. 페이지당 3–6문장.
- 실습 페이지 노트에는 진행 시간과 강사가 돌아다니며 확인할 포인트를 말로 풀어 넣는다
  (TTS 규칙상 괄호 태그·"요점:" 목록 금지 — 문장으로 쓴다).
